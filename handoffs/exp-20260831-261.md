- Mechanism: build one `token -> canonical expanded A row` map from `token_ids`, then load A for every route of that token from the same row.

## Decision

- Recommendation: reject without repeat or OJ.
- Observed result: case 2 improved consistently but only `0.9517%`, far below the complete-path `5.967%`; case 4 regressed consistently by `0.6156%` instead of improving the required `6.847%`. The two dependent metadata loads also raised ST pressure by 12.

- OJ boundary: no submission because the complete case-2/case-4 leaderboard path failed.
- Follow-up: preserve the validated semantic mechanism only as evidence for a fresh lane that removes the dependent `token_ids -> canonical-token-map` lookup from the main kernel; it must still meet the full leaderboard gate independently.
