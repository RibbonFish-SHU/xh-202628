## Proof And Tests

- Address/coverage proof: the formal `128x128x128` CTA stages one 16 KiB A tile and one 16 KiB B tile per K step, for 32 KiB total. Two serial N64 phases still need the same 16 KiB B footprint in aggregate, but each phase needs the full 16 KiB A tile because all 128 M rows participate. Without retaining A across phases, staged A doubles from 16 KiB to 32 KiB while B remains 16 KiB, increasing staged matrix bytes from 32 KiB to 48 KiB per K step, exactly `50%`. Retaining A while loading the second B half requires 16 KiB A plus two 8 KiB B halves before accounting for pipeline storage and does not remove the serial MMA work or lifecycle barriers
- Occupancy proof: a 48-KiB shared allocation has not raised static residency above the formal path on C500; formal case 2 already reports `staticMaxWarps=2`. Therefore the only modeled saving is fewer CTA launches/exits, while all matrix loads, LDS, MMA, 111 barriers per N tile and epilogue work remain. No measured or instruction-count model attributes `>=2.72%` of case-2 time to CTA lifecycle
