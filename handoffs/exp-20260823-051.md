## Proof And Tests

- Cache-validity proof: exact-key memoization behaves correctly for alternating shapes only while each shape uses a different `(a,out)` pair, and failures can be kept uncached. It cannot distinguish a later allocation generation that reuses the same two virtual addresses. A deterministic model first associates `(0x10000000,0x20000000)` with case 1 `(4096,4096,7168)`, then reuses that exact tuple for case 3 `(4096,7168,2048)`; the memo returns case 1 while the exact allocation-size query returns case 3. The model also confirms separate tuples infer cases 2 and 4 and an unknown allocation fails without caching. Caching the prior base/size does not help because those values are themselves stale after reuse.
- Lifetime/API proof: `run_kernel` receives raw pointers but no shape, allocation owner, lifetime token, generation, free callback, stream-owned context or allocator hook. The only available target API used and documented by the official starter is `wcuMemGetAddressRange(&base,&bytes,pointer)`, which returns the current allocation's base and bytes but no generation. `cudaPointerGetAttributes` exposes current pointer properties, not a target-portable allocation generation. A fresh range query on every hit is the exact baseline path and eliminates the proposed saving. No documented MACA allocation-ID API is present in the repository, official source clone or supplied contract; guessing a `wcu` attribute spelling would be outside the assigned mechanism and cannot establish target semantics.
- Concurrency proof: a global last-entry cache can avoid torn `(pointer,config)` publication only with a lock, versioned atomics or equivalent synchronization; a thread-local cache avoids data races. Neither strategy fixes sequential same-thread ABA reuse. Therefore even perfect serialization cannot make the memo contract-safe. The public contract does not guarantee stable allocation lifetime across calls, single-threaded invocation, or no address reuse.
- Minimum-savings proof: the exact performance-baseline source was already measured in committed proxy/NVIDIA run `exp-20260823-049-6fe3b7194b38-a01`. Its one-query A-primary `infer_public_config` median was 94.5 ns (additional repeated runs 93.9 and 94.0 ns); the two-query reference was 190.6 ns. Even an impossible zero-cost cache can save at most about 0.095 us on the normal valid path, over 21 times below the assigned 2-us stop threshold and about 0.01% of a 1-ms decode case.

## Decision

- Observed result: two independent stop conditions fired. Pointer-tuple memoization is stale after legal same-address allocation reuse, and the interface/API surface supplies no portable generation or invalidation event. Separately, the measured normal-path query is only about 0.095 us, far below the 2-us minimum-savings gate.

A future documented MACA allocation-generation API could close the ABA gap, but querying it on every call would need its own measured cost and a new experiment.
