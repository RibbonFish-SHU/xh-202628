## Hypothesis

- Target exact sorted prefill cases 2 and 4, both with `EM=32768`.
- The validated prefill model contains eight active experts with 32 M tiles each. Stable within-expert routing gives the same token at the same local row for corresponding tiles across experts.
- Preserve each width-eight same-expert M cluster, but order clusters as token-slice group first and expert second. The next seven expert clusters then consume the same eight canonical A tiles while all eight CTAs in each cluster retain formal B reuse.
- Runtime validation checks all 128 token rows of every tile against the corresponding tile of the first active expert. A mismatching tile uses its own A row, and a distribution other than exact `8 x 32` uses formal stable sort order.
- Modeled maximum physical A-read savings are `205,520,896 B` (`196 MiB`) for case 2 and `58,720,256 B` (`56 MiB`) for case 4. This is the first canonical-A mechanism that preserves the formal width-eight B cluster while shortening A reuse distance.

## Decision

- Recommendation: reject without repeat or OJ.
- Observed result: the aligned-route upper-bound model regressed both target cases despite preserving formal main-kernel resources. The builder scan/synchronization and changed physical order outweigh the modeled A-cache reuse; neither case has evidence for the required leaderboard tier.
- OJ boundary: no submission was made because the measured result does not support the complete three-point path to at least `85.50`.
- Ordering uncertainty: the official public repository does not expose the large OJ route generator. The candidate therefore validates alignment at runtime, while the calibrated C500 route model measures the plausible aligned upper bound rather than asserting hidden OJ order.
- Follow-up: close slice-major/expert-minor cluster interleaving and further canonical-A scheduling variants that depend on this same builder/order premise; keep the formal source exact and move to a structurally independent mechanism.
