## 唯一 OJ 通道

严格执行 `skills/xpuoj-operator-optimizer/references/submission-protocol.md`：

```text
queued -> ready -> claimed -> armed -> judging -> finalized
                                               `-> reported（延迟标记，不占槽）
```

- 会话启动时检查 canonical DB、primary mirror 的 digest/dirty 状态并获取 controller。token/epoch 只是同一操作系统用户下的协作式 fencing，不是安全隔离。takeover 只在确认旧 Main Agent 已停止后执行，必须提供 recovery token 和刚核对的旧 owner/epoch，且绝不自动清除 active claim。
- `claim` 使用稳定 request ID。最终 submit click 之前必须先 `arm`。
- 只提交控制器返回的 committed source，只点击一次；出现 submission ID 后立即 `bind`。
- 等待终态并保存证据；排队/编译中不能当终态，也不能重提。
- Accepted、编译错误、Wrong Answer、运行错误、超时、取消和零分都必须 `finalize`。
- 终态后执行 `finalize`，保存提交 ID/时间、commit、语言/方案、正确性、分数/排名/各点、相对变化、proxy 证据和决定；`finalize` 释放槽位。
- 完成必要的正式 best 更新或失败恢复、状态更新和 commit/push 后继续下一次 OJ，不等待我回复，也不主动发送逐次打榜报告。
- 当我主动打断、询问状态、任务结束或出现必须由我处理的阻塞时，运行 `unreported-list`，向我一次性汇总全部尚未报告的提交；消息实际发出后再逐条执行 `report`。

如果 `armed` 后崩溃或页面异常，先检查 OJ 历史：找到记录就绑定；只有确认没有提交，并保存历史证据文件、核对时间且核对 armed source hash 后，才允许 `abandon --confirmed-no-submit`。不能确认时保持阻塞，绝不重复点击。
